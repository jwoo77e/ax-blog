## 요약

어제(5/21 목요일)는 자동 트랙 두 개(AI 트렌드 메일 · IRIS 연구과제 크롤러)가 정시에 흘렀다. 그 위에서 사람이 손을 댄 건 한 가지로 모인다 — **Notion의 「AX 전환」 페이지를 4축 KPI 구조로 처음부터 다시 짠 것**. 부수적으로 Gemini 3 Flash 이미지 분석 단가도 시뮬레이션해 봤고, 제로비 사진 크롤링은 일부 한계를 확인했다.

## 1. 자동 트랙 — 두 개 다 정시

**AI 트렌드 메일**은 2026년 5대 흐름(Agentic AI · Multimodal · Edge AI/SLM · VLM · Reasoning Models)을 산업안전 관점으로 재해석해 발송됐다. 핵심 한 줄은 "더 정확한 탐지가 아니라 '왜 위험한가'를 추론하고 '무엇을 해야 하는가'까지 자율 실행하는 에이전트형·멀티모달·Edge 통합이 승부처"다. 오탐과 통신 한계라는 한국 현장의 두 고질병을 VLM(컨텍스트 추론)과 Edge AI(오프라인 처리)로 풀고, 그 위에 에이전트 레이어를 얹는 그림이다.

**IRIS 크롤러**는 7일 윈도우 안에서 49건을 잡았다. AI 관련 5건, 마감임박 31건. 산업안전 분야는 0건이라 솔직하게 0으로 보고했다. 이번 회차에서도 Chrome MCP `file_upload` 버그가 재발해서 첨부가 안 됐다 — 이틀 연속이다. **본문 인라인 fallback이 사실상 표준 절차로 굳어진다.** 메모리에 이 함정 한 줄을 갱신해 뒀다. 또 하나, Gmail compose에서 Tab으로 받는사람 → 제목 이동이 불안정하게 실패하는 패턴을 새로 발견해서 DOM `setter` 방식으로 우회한 것도 기록.

## 2. AX 전환 페이지 — 「현황판」으로 다시 짜기

손이 가장 길게 머문 곳은 Notion의 「🔄 AX전환」 페이지였다. 기존 페이지는 "도구 사용량·비용"만 들고 있어서 전사 AX 수준을 한 줄로 답할 수가 없었다. 그래서 **4축 KPI 현황판**으로 처음부터 다시 짰다.

산식은 이렇게 잡았다.

- **사용 확산 25%** — 활성 사용자 / 활용 다양성
- **업무 전환 35%** — 실제 업무에 붙은 Use Case 수와 단계(후보·파일럿·운영·확산)
- **성과 검증 25%** — 시간 절감·품질·비용 효과
- **운영 정착 15%** — 프롬프트·SOP 정착 수

이 산식으로 산정해 보니 **전사 AX 전환율 17%**가 나왔다. 단, 자동 측정이 가능한 건 "사용 확산" 한 축뿐이다. 나머지 세 축은 측정 인프라가 아직 없어서 솔직히 "미산정"으로 표시했다. 숫자를 부풀리지 않기로 한 선택.

페이지에는 같이 들어간 게 더 있다.

- **부서별 AX 성숙도 맵(0~5단계)** — 기술연구소 4단계, 스마트서비스/전략사업팀은 0단계. 솔직한 격차.
- **AX Use Case 파이프라인** — 후보/파일럿/운영/확산 4단계
- **위험 신호 8가지** — 고성과자 1명에 사용량이 96% 몰린 점, 자금회계팀이 공용 계정으로 96.3% 흡수되는 점, 0단계 부서들

스케줄러도 같이 갱신했다. `ax-kpi-daily-update` 작업은 "자동으로 갱신해도 되는 영역"과 "사람 판단 필요 영역"을 명시적으로 갈라 뒀다. 자동: 마지막 업데이트 시각, 전사 전환율, 도구별 비용·비중·활성 사용자, Use Case 파이프라인 활용 영역. **자동 금지**: 부서 성숙도, 성과 검증, 운영 정착, 집중 개선 과제. 이걸 분리해 두지 않으면 다음번 어떤 회차에서 자동이 사람의 판단을 덮어쓴다.

이번 달 집중 개선 과제 Top 1은 **AX Use Case 보드 구축**으로 잡았다. 이게 있어야 35% + 25% = 60% 축이 살아나서 17%라는 숫자가 진짜 의미를 가진다.

## 3. 부수 작업 두 가지

**Gemini 3 Flash 이미지 분석 단가**도 시뮬레이션해 봤다. 이미지 1장 + 프롬프트 500토큰 + 응답 500토큰 기준으로 장당 약 $0.0023, 환율 1,400원 기준 **3.2원**. Batch API 쓰면 절반인 1.6원까지 내려간다. BiRAG에서 대량 사진 분석을 돌릴 때 비용 곡선이 어떻게 그려지는지 한 번 짚어 두는 차원이다. 10만 장 = 32만 원, 100만 장 = 323만 원. 현장 사진 규모 감각이 잡힌다.

**제로비 사진 크롤링**은 한계를 확인한 회차였다. 363개 사진을 base64로 받아서 엑셀에 직접 임베드하려 했는데, 한 번에 받을 수 있는 base64 데이터가 약 1,200자로 제한돼 사진 3장 단위로 끊기더라. 318장 전부를 임베드하려면 100회 이상 호출이 필요해서 18장(교육 9 + TBM 9)만 임베드하고 나머지는 다운로드 안내로 대체했다. **자동이 풀지 못하는 영역이 어디인지 명시해 두는 것**도 자동화의 일부라는 걸 다시 확인.

## 4. 배운 것

- KPI는 자동 측정되는 축만 진짜 KPI다. 측정이 안 되는 축을 "미산정"으로 두는 게 부풀리기보다 낫다.
- Chrome MCP의 `file_upload` 버그는 이틀 연속 재발. fallback이 표준이 됐다는 사실 자체를 기록해 둘 가치가 있다.
- 자동 갱신과 사람 판단의 경계는 코드가 아니라 **운영 문서에 명시**해야 한다. 안 그러면 다음 회차가 덮어쓴다.

오늘은 자동이 정시에 흐른 위에서, 사람이 다음 단계의 측정 인프라를 한 단계 깐 날이었다.
