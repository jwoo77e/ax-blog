## 요약

어제(5/18 월요일)는 자동 트랙 3종이 09시대에 정상적으로 흘렀고, 그 위에서 손은 BiRAG 설명자료와 VLM BiRAG 발표자료 두 갈래로 갔다. **자동화는 사용자 액션 0건, 사람 작업은 슬라이드 5장 추가**가 정확한 회차 구성이었다. 마지막으로 21시대 네이버 블로그 자동 회차가 한 번 더 깨어났다.

## 1. 자동화 3종 — 09시대 정시, 사용자 액션 0건

IRIS 일일 크롤러는 09:00에 11건을, 7일 윈도우는 09:47에 58건(접수중 47 + 접수예정 11)을 보냈다. AI 트렌드 메일은 09:13에 발송됐다. 5/17 일요일에 Chrome MCP를 재연결해 둔 상태가 그대로 유지돼서 자동 첨부·자동 발송이 다 살아 있었다.

AI 분야 6건 중 핵심은 여전히 과기정통부의 **S&T4AI**와 **AI4S&T** 두 건(5/22 마감, D-4), 그리고 산업통상부의 **산업용 무기·유기화합물 제형물성 예측 AI 파운데이션 모델**(D-11)이다. **산업안전 키워드는 5일 연속 0건**. 룰 v2 결재가 더 급해졌다.

마감 임박 D-Day 0-7은 27건. 그중 D-0(5/18) 마감 4건은 월요일 오전 패스 여부 컨펌이 필요했다.

## 2. 일일업무보고 — EU AI Act 트랙 결정 포인트

자동 발송 3건을 한 페이지로 묶었다. 표지에 의사결정 3건을 박았다.

먼저 **산업안전 룰 v2.** 5일 연속 0건이라 더 미룰 수 없다. 회신이 없으면 임시 룰을 더한 다음 사후 결재로 정리하기로 했다.

다음 **D-1 4건.** 과기정통부 3건(방송통신정책연구 / 자동차반도체 / 광기반 연산반도체)과 우주항공청 1건(우주항공 글로벌 인력양성). 월요일 오전 안에 결정.

마지막 **EU AI Act 옴니버스 개정안.** 고위험 AI 적용 연기로 인증 트랙 두 갈래가 떴다. **Machinery Regulation(2027-12-02)** vs **AI Act(2028-08-02)** 중 어느 쪽으로 정렬할지 5/22까지 방향을 잡기로 했다.

## 3. BiRAG 설명자료 — 표현을 정밀화한 슬라이드 3장

오후 첫 트랙은 BiRAG_설명자료.pptx에 슬라이드 3장을 더한 작업이었다. 원본 26장 뒤에 27-29장이 들어갔고 기존 페이지 번호도 일괄 업데이트했다.

**27장 — 두 가지 핵심 장점 주장.** 「할루시네이션 해결」 → 「구조적 완화 + 근거 추적성」, 「100% 로컬 = 안전」 → 「공격 표면이 작고 망분리 친화적」으로 표현을 정밀화. 빨강·녹색 2×2 비교로 원안과 권장 표현을 나란히 뒀다.

**28장 — RAG가 막는 것·못 막는 것.** 「지식 환각은 줄인다」를 전제에 두고 못 막는 3가지(지각 환각, 검색 실패, 문서 오독)와 각각의 대응 방안(인간 검수, 하이브리드 검색, TPP 단계 분해)을 3열로 정리.

**29장 — 진짜 보안은 통제로 결정된다.** 로컬이라도 발생하는 위험 5종(접근통제 부재, 권한 미분리, 디스크 평문, 감사 로그 없음, 네트워크 미분리)과 망분리 친화 구조가 주는 가치 5종(송신 0, 망분리 배포, TCO 우위, 모델 주권, 컴플라이언스 적합)을 1:1로 대조.

배운 것: "100% 로컬이라 안전"은 영업용으론 좋지만 검토 자리에선 깨지기 쉬운 표현이다. **「로컬 + 접근통제 + 암호화 + 감사 로그」가 합쳐져야 진짜 보안**이라는 한 줄을 결론에 박는 게 더 길게 간다.

## 4. VLM BiRAG 구현방향 v8 — CCTV 영상 규모 시뮬레이션 2장

오후 후반은 발표자료 v7 → v8 작업이었다. 슬라이드 22, 23 두 장이 새로 들어갔다.

**22장 — CCTV 영상 데이터 규모 시뮬레이션.** 소·중·대 3 규모로 일일 Raw → Edge → 서버 → 위험 확정 영상량을 한눈에 비교. 중규모 200대 행에 ★ 표시. 막대 펀넬로 통과율을 시각화: Raw 100%(2.16 TB) → Motion 22%(475 GB) → Person 8.8%(190 GB) → Action 0.88%(19 GB) → VLM 0.23%(5 GB) → 적재 0.05%(1 GB). 옆에는 Bird 안전 피라미드(사망 1 : 중상 10 : 경상 30 : 아차 600 : 위험 행위 3,000+)로 시뮬레이션 수치의 현실 적합성을 교차 검증.

**23장 — 최적 서버 구성안 + TCO.** 4 노드 Modular Cluster (Application / **GPU Inference (H100 80GB + L40S × 2)** / Storage 380TB / Vector DB 1TB DDR5) 사양과 단계적 도입 로드맵(Phase 1 MVP → Phase 2 본격 → Phase 3 HA). 5년 TCO 비교표는 규모별로 단가 차이를 정량화. 큰 돈을 한 번에 쓰지 않고 단계적으로 갈 수 있다는 점을 한 슬라이드에 묶었다.

검토 자리에서 가장 자주 나오는 세 질문 — **「비용은? 처리량은? 단계적으로 갈 수 있나?」** — 에 한 번에 답하는 흐름이 v8에서 완성됐다.

## 5. 네이버 블로그 — 21시대 보너스 회차

저녁 21시대에 네이버 블로그 자동 회차가 한 번 더 깨어났다. 이미 같은 21시 회차가 처리된 상태라 기존 폴더를 백업한 뒤 새 글로 덮어썼다. 주제는 「엑셀 314줄 고객 피드백을 5개 테마로 4분 만에 자동 분류한 절차」 — 지시문 작성 → AI 분류 → 사람 검증 → 액션 표 4단계의 실용 후기형 글이다. `gpt-image-1` 이미지 2장도 정상 생성됐다.

다만 누적 미해결 사안 하나 — `2_5_image_gen.py` 의 `dall-e-3` → `gpt-image-1` 본체 수정은 6일째 미적용 상태다. 인라인 폴백으로 발행은 막힘 없지만, 다음 launchd 정주행에서 이미지 단계는 계속 실패한다. 본체 수정은 별도 트랙으로 처리해야 한다.

## 배운 것

- 자동 트랙은 일단 한 번 깔리면 손이 줄어든다 — 5/16 Chrome MCP 끊김 회차 vs 어제처럼 0회 입력 회차의 시간 차이는 크다.
- 검토 자리에서 깨지지 않는 표현은 항상 **단정형이 아닌 조합형**이다. 「100% 로컬이라 안전」보다 「로컬 + 통제 + 암호화 + 로그」가 길게 간다.
- 「비용·처리량·단계적 도입」 세 질문은 어떤 인프라 자료에도 미리 답을 준비해 두는 게 맞다 — 한 슬라이드에 묶으면 회의가 짧아진다.
