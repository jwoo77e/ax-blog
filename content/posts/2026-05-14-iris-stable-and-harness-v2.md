## 오늘 한 일

세 덩어리였다. **IRIS 크롤러 두 번 정주행**(아침·오후), **그 결과를 받아 일일업무보고를 자동 생성**, 그리고 **AX 마스터플랜 v2에서 Harness 메시지를 4슬라이드에 일관되게 흐르도록 정합**. 코드는 거의 건드리지 않았고, AI 툴(Claude + PowerPoint MCP + 워크스페이스 bash)이 안 보이는 시간이 길어졌다. 자동화는 잘 굴러갈 때가 가장 조용하다는 — 익숙해진 풍경이다.

## IRIS 크롤러 — 어제 한 번 흔들린 뒤의 정상화

어제(5-13) 회차는 첨부 파일이 0바이트로 나가 한 번 흔들렸다. 오늘은 같은 함정에 다시 빠지지 않도록 세 가지를 잡고 갔다 — ASCII 파일명으로 통일, 다운로드 직후 충분히 대기, IRIS 탭은 크롤이 끝날 때까지 유지. 결과적으로 09:00 KST 일일 리포트와 13:58 KST 7일 윈도우 리포트 모두 첨부 정상으로 발송됐다.

7일 윈도우 기준 수집은 **59건**(접수중 52 / 접수예정 7), 그중 **AI 관련 7건**, **마감 임박(D-7 이내) 28건**. 산업안전 분야 직접 매칭은 0건이었다 — 이 한 줄이 오늘 리포트에서 가장 신경 쓰인 항목이다. "안전"이 들어간 공고는 식품의약품안전·국민생활안전 쪽이었고, 정작 산업안전보건 카테고리는 빈 상태였다. 키워드 룰을 더 넓혀야 하는지, 아니면 그 기간 진짜 공고가 없었던 건지 — 다음 한 주 동안 두세 번 더 정주행하면서 확인할 항목으로 메모.

접수예정 5,536건 전체 크롤은 페이지당 12초씩 걸려 시간 안에 다 못 돌렸다. 200페이지까지만 스캔하고 윈도우 매칭은 1페이지에 8건 집중·50페이지 이후는 날짜 필드가 비어 있어 누락 위험은 낮다고 판단해 끊었다. **"끝까지 돌렸다"가 아니라 "어디까지 의미 있고 어디부터 빈 응답인지"를 본 결과로 마무리하는 게** 자동 정주행에서 이번에 새로 배운 정리법이다.

## 일일업무보고 — 메일 송신 기록을 그대로 보존

크롤러가 멈춘 직후 AI 툴로 곧장 일일업무보고를 만들었다. Word와 Markdown 두 포맷. 핵심은 **자동 결정 사항을 본문 안에 명시**한 것이다. 산업안전 매칭 0건은 단순 "0건"이 아니라 "키워드 룰 확장 필요사항"으로 격상해 이슈란 최상단에 배치했고, 마감임박 D-day(D-3 월요일 도래 기준)에서 협조요청 결재 시한을 역산해 일정에 박았다.

오늘 회차에서 의도적으로 지킨 한 가지는, **9시·13시 송신 시각과 메일ID, 첨부 파일명을 보고서 본문에 그대로 보존**한 점이다. 회차마다 "정말 보냈는지"를 매번 확인하지 않아도 되도록, 송신 기록 자체가 보고서의 출처가 되게 만들었다. 어제 첨부 누락 이슈 회수에서 한 가지 배운 적용이다.

## AX 마스터플랜 v2 — Harness 키워드로 4슬라이드를 한 줄에 꿰기

오후에는 마스터플랜 v2를 열어 **Harness 메시지를 4슬라이드에 일관되게 흐르도록 정합**했다. 손댄 페이지는 네 장.

- **3페이지(진단)** — "SI 90% + 개발 워크플로우 Feedforward-only" 한 줄을 박고, 그 아래에 "근본: Harness 부재 → 자율운영 + SI Dev Harness 이중 처방"으로 처방의 방향을 못 박았다.
- **5페이지(Pillar 1 Use Case)** — Top Use Case에 "코드 리뷰·문서화·테스트 자동화 + Eval Harness 루프"를 박고, 활용 도구에 "Claude Code + MCP / Eval Suite", 기대 효과는 "SI 생산성 +25%, 사람개입 -70%"로 묶었다.
- **6페이지(Pillar 2 인프라 4트랙)** — Track D를 "Dev Harness (Claude Code Eval Loop)"로 신설하고 KPI를 **"이터레이션당 사람 개입 8회 → 2회"**로 박았다.
- **9페이지(개발팀 12개월 로드맵)** — Q1 진단 + Harness 설계 → Q2 Claude Code + Eval Harness PoC → Q3 SI 산출물 자동화 + Feedback Loop → Q4 테스트·QA Agent (자율 이터레이션) 으로 분기를 다시 잘랐다.

이 네 페이지가 손에 맞물려 들어가니, **진단(병목) → 처방(Use Case) → 인프라 트랙(Track D) → 분기별 실행(로드맵)** 4단 논리가 Harness 한 단어로 꿰어진다. 핵심 KPI인 "이터레이션당 사람 개입 횟수"가 6페이지에 박혀 있고, 9페이지의 분기 단계가 그 KPI를 단계적으로 깎아 내려가는 경로가 된다. v1 거버넌스 슬라이드가 "한 장만 다시"였다면, v2는 "한 줄로 네 장을 꿰기"였다.

## AI 툴은 어떻게 썼나

세 작업 모두 직접 코드를 거의 안 짰다. IRIS 크롤러는 어제 함정에 빠졌던 부분(파일명·대기시간·탭 유지)만 자연어로 지시해서 고쳤고, 일일업무보고는 "송신 기록을 본문에 보존, 자동 결정 사항을 이슈란 최상단에" 두 줄 정도의 지시로 흘렸다. 마스터플랜 v2는 PowerPoint MCP에 "3·5·6·9페이지에 Harness 키워드가 한 줄로 흐르게, 다른 페이지는 건드리지 마"로 끝났다.

**도구가 빨라지니 사고가 병목**이라는 말을 어제 마스터플랜 v1 정리할 때도 적었는데, 오늘은 한 단계 더 가서 — 도구를 부르는 자연어 자체가 의사결정의 결과물이라는 느낌이 들었다. "어디까지 돌릴 것인가", "무엇을 그대로 보존할 것인가", "어느 키워드를 네 장에 꿸 것인가" — 결정만 분명하면 도구는 한 번에 따라온다.

## 무엇을 배웠나

세 가지가 남았다.

첫째, **자동화는 잘 굴러갈 때 가장 조용하다**는 점을 오늘 다시 확인했다. 어제 흔들렸을 때는 메일 두세 통이 오가고 첨부를 다시 보내고 본문에 사과를 쓰고 하면서 시끄러웠는데, 오늘은 두 번 정주행이 끝나도록 알람 하나 울리지 않았다. 조용한 자동화가 좋은 자동화다 — 라는 익숙한 명제를 오랜만에 실측한 느낌.

둘째, **"끝까지 못 돌렸다"를 결함으로 기록할 게 아니라 "어디까지 의미 있는지"로 정리하는 게 자동 정주행의 정답**에 가깝다. 5,536건 전체를 못 돈 것 자체가 문제가 아니라, 200페이지 이후로 빈 응답이 이어진다는 근거를 같이 적어 두면 다음 회차의 회의가 절반으로 줄어든다.

셋째, **마스터플랜 같은 전사 문서는 "한 단어로 네 장을 꿰기"가 한 장 다시 그리기만큼 단단하다.** 어제는 거버넌스 한 장만 갈았고 오늘은 Harness 한 단어를 네 장에 박았는데, 둘 다 변경 범위가 좁다는 공통점이 있다. 좁은 변경이 회의실에서 가장 빨리 통과된다 — 이 명제가 v1·v2 두 회차에서 같은 형태로 확인된 게 오늘의 작은 수확이다.

다음 회차 전까지는 IRIS 산업안전 키워드 룰 확장과, 마스터플랜 v2의 Track D KPI("이터레이션당 사람 개입 8→2")가 실제 SI 프로젝트 한 건에서 측정 가능한지 사내 한 분과 짧게 맞춰보는 일을 처리할 생각이다. 도구를 부르는 자연어가 점점 짧아지는 만큼, 그 자연어가 가리키는 결정의 정확도가 다음 한 주의 일이다.
